# The API contract is OpenAPI generated from Go with huma

The API is defined by typed Go input and output structs registered with huma v2, which runs on top of the standard `net/http` ServeMux. huma validates requests, returns 400 errors with field paths, and serves `/openapi.json` and a browsable `/docs` page. The web client's types, fetch functions and TanStack Query hooks are generated from that spec with `orval`, all routed through one hand-written fetcher that throws `ApiError` with field paths, and CI fails if they are stale. We chose this over `tygo` (types only, with a hand-written client and no contract) and over Connect-RPC (a heavier toolchain, and awkward for evidence unions). Evidence is a discriminated union, one struct per condition type, so the UI can narrow on `type`.

**Update 2026-11-20: orval instead of openapi-typescript + openapi-fetch.** We moved to TypeScript 7, the native compiler. Its npm package no longer exposes the JavaScript compiler API that `openapi-typescript`, `@hey-api/openapi-ts` and `swagger-typescript-api` use to print code, so they fail under TS 7. `orval` writes code as text, works with TS 7, and also generates the TanStack Query hooks we were writing by hand.
