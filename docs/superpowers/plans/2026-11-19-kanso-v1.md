# Kanso V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Kanso V1: a Go engine and React web app that scans NSE stocks for multi-year breakouts (Scanner, Quick Scan, Stock Report) and backtests no-code breakout systems honestly, checked against a vectorbt benchmark.

**Architecture:** Go module with focused engine packages (`market` → `patterns` → `rules` → `backtest` / `scan` / `report`) over a `market.Provider` interface. SQLite (WAL, pure-Go driver, no cgo) implements the provider in production and an in-memory provider is used in tests. A huma v2 JSON API on `net/http` publishes an OpenAPI 3.1 spec, from which the Vite + React + TypeScript app's typed client is generated. Nightly ingest is a separate process. A dev-only Python tool produces vectorbt golden files that a Go test compares against.

**Tech Stack** (spec §4.1, ADRs in `docs/adr/`): Go 1.27 (std `net/http` + `github.com/danielgtaylor/huma/v2`, `log/slog`, `golang.org/x/sync/errgroup`, `golang.org/x/time/rate`, `github.com/google/go-cmp`), SQLite via `modernc.org/sqlite` (WAL, `CGO_ENABLED=0`), `sqlc` + `github.com/pressly/goose/v3`, `github.com/parquet-go/parquet-go` (export only); Node 26 + pnpm, Vite, React 19, TypeScript 7, TanStack Router + Query + Table, Tailwind v4 + shadcn/ui, TradingView Lightweight Charts, `orval` (generated fetch functions + TanStack Query hooks), Vitest + React Testing Library, Playwright; Python via `uv` + vectorbt + pyarrow (benchmark tool only); GitHub Actions, CodeRabbit, Google Cloud Run.

**Spec:** `docs/superpowers/specs/2026-11-19-kanso-breakout-scanner-design.md`. Section numbers (§) below refer to it. Read it alongside this plan.

## Global Constraints

- Go module path: `kanso`. All engine code lives under `internal/`, and commands under `cmd/`.
- Daily data only, split-adjusted OHLCV (§5). A bar at index t may use data only up to and including t's close.
- Dates are `market.Date` strings in `YYYY-MM-DD` (IST trading date). Compare them as strings.
- Defaults (§5.2–5.6, §7.3), exactly: years 3; volume k 2.0, `window_weeks` 10; RS `rs_months` 6 vs `^NSEI`; level age `min_age_years` 1; not-extended 8%; stop 8%; trend SMA 30 weeks; costs 0.20% per side; slippage 0.10% per side; capital 1,000,000; max positions 10; scanner fresh window 5 daily / 1 weekly bars.
- Lookback: `years × 252` daily or `years × 52` weekly bars. "All-time" needs at least 504 daily / 104 weekly prior bars.
- Calendar units (§5.3): every duration param is stored in weeks/months/years and converted with `patterns.ToBars`: daily week 5, month 21, year 252; weekly week 1, month round(52/12 × n), year 52. No param is in bars.
- Signals are edge-triggered on **evaluable** bars: `Pass(t) && Evaluable(t−1) && !Pass(t−1)` (§5.5).
- Numbers (ADR 0004): float64 for prices, indicators, percentages, cash and equity; int64 for share quantities (whole shares, floor). Float comparisons in tests use 1e-9 relative tolerance.
- Every API-facing Go struct has explicit snake_case `json` tags.
- `CGO_ENABLED=0` for every build; the binary is fully static. (Only `go test -race` in CI enables cgo.)
- Data gap: more than 5 consecutive benchmark trading days missing for an instrument counts as a gap (§6.1).
- The Go test suite must not need Python, the network, or a pre-built database file, except for tests that skip themselves when an env var is unset (temp SQLite files created by the test are fine).
- Everything is deterministic: no map-iteration order in outputs, and stable sorts with explicit tie-breaks.
- No code from `v0/` is imported or copied.
- Pin exact versions for every npm (pnpm) and Python dependency at install time (lockfiles committed).
- User-Agent for Yahoo requests: `kanso/0.1` (no personal data in requests).
- Demo mode: system writes return 403, there's a per-IP rate limit, `/api/bars` serves one symbol per request with at most 5,000 bars, and the footer credits Yahoo as the data source (§6.4).

## Review Focus

Inputs the spec implies but no other test exercises, most likely to bite first. Each one's test is added to the task named.

1. **Yahoo rows with nulls, duplicate dates, or zero volume.** Expected: null-price rows are dropped, a duplicate date keeps the last occurrence, and zero volume is kept as 0. Tested in Task 9, `TestParseChartDropsNullsAndDedupes`.
2. **Instruments with less history than the lookback, or listed after the start date.** Expected: "not evaluable", never a panic or index-out-of-range. Tested in Task 10, `TestScanShortHistoryInstrument`.
3. **Benchmark missing a date the stock has.** Expected: RS is not evaluable on that bar, and other conditions still evaluate. Tested in Task 4, `TestRelativeStrengthMissingBenchmarkBar`.
4. **Zero denominators** (50-day average volume 0, close[t−n] = 0). Expected: the condition is not evaluable, not Inf or NaN. Tested in Task 4, `TestFiltersZeroDenominators`.
5. **Stale instruments** (last bar older than the benchmark's last bar, e.g. delisted or suspended) in a "today" scan. Expected: excluded from matches and counted in `ScanResult.Stale`. Tested in Task 10, `TestScanExcludesStaleInstrument`.

**Interfaces:**
- Consumes: Task 1 types.
- Produces:
  - `func (s *Series) MarkGaps(calendar []Date, maxMissing int)`. Here `calendar` is the benchmark's dates.   - `var ErrNotFound = errors.New("not found")`

### Task 3: Pattern framework and the N-year high

**Files:**
- Create: `internal/patterns/{pattern.go,params.go,context.go,registry.go,nyearhigh.go}`
- Test: `internal/patterns/nyearhigh_test.go`, `internal/patterns/registry_test.go`

**Interfaces:**
- Consumes: `market.Series`, `market.Date`.
- Produces:
  - `type ParamKind string` (`"number"`, `"bool"`, `"symbol"`); `type Unit string` (`""`, `"weeks"`, `"months"`, `"years"`); `type ParamSpec struct { Name, Label string; Kind ParamKind; Unit Unit; Default any; Min, Max float64; Step float64 }`
  - `func ToBars(n float64, u Unit, tf market.Timeframe) int` (units.go): daily week 5, month 21, year 252; weekly week 1, month round(52/12 × n), year 52. Rounds to the nearest bar. Test `TestToBarsMatchesSpecDefaults` (10 weeks → 50/10, 6 months → 126/26, 1 year → 252/52, 3 years → 756/156).
  - `type Params map[string]any`; `func (p Params) Float(name string) float64`; `func (p Params) String(name string) string`
  - `type Meta struct { Type, Label, Description string; Params []ParamSpec; Provides, Requires []string }`
  - `const BreakoutLevel = "breakout_level"`
  - Typed evidence (evidence.go, ADR 0003): `type Evidence interface { EvidenceType() string }`. One struct per condition type with snake_case JSON tags and a `Type string \`json:"type"\`` discriminator, e.g. `NYearHighEvidence{Type, Level, LevelDate, BarsSince, Close, PctAbove}`; plus `NotEvaluable{Type: "not_evaluable", Reason string}` where Reason ∈ `insufficient_history | data_gap | benchmark_missing | no_breakout_level | zero_denominator | incomplete_bar`. `func Evidences() []Evidence` lists one zero value of every variant (used by the OpenAPI schema in Task 12).
  - `type Result struct { Pass, Evaluable bool; Evidence Evidence }` (JSON `pass,evaluable,evidence`). Not-evaluable results carry `NotEvaluable`.
  - **Reading the tests below:** assertions are written as `Evidence["key"]` for brevity. With typed evidence they are struct fields: `Evidence["level"]` means `ev.(NYearHighEvidence).Level`, and `Evidence["reason"]` means `ev.(NotEvaluable).Reason`.
  - `type Context struct { Series *market.Series; Bench *market.Series; BenchIdx []int; Level []float64; LevelIdx []int }`. `BenchIdx[i]` is the bench bar with the same date (daily) or the same ISO week (weekly), or −1. `Level` and `LevelIdx` are filled in by a provider; `LevelIdx[t] = -1` means no level.
  - `func NewContext(s, bench *market.Series) *Context`
  - `func Load(ctx context.Context, prov market.Provider, inst market.Instrument, benchDaily *market.Series, tf market.Timeframe, from, to market.Date) (pctx *Context, daily *market.Series, err error)`. This is the one loading path used by backtest, scan, report and the API. It runs `NewDaily`, then `MarkGaps(bench dates, 5)`, then `Weekly` for both stock and bench when `tf` is weekly, then `NewContext`.
  - `type Pattern interface { Meta() Meta; Prepare(ctx *Context, p Params) error; Eval(ctx *Context, p Params, t int) Result }`
  - `type Registry struct{...}`; `func NewRegistry(ps ...Pattern) *Registry`; `func (r *Registry) Get(typ string) (Pattern, bool)`; `func (r *Registry) All() []Meta` (sorted by Type); `func Default() *Registry` (all V1 patterns, finalised in Task 4)
  - `func Normalize(m Meta, p Params) (Params, error)`, which fills defaults and rejects unknown names, wrong kinds and out-of-range values.
  - `NYearHigh`: type `"n_year_high"`, param `years` (number, unit years, default 3, 1–20) plus `all_time` (bool, default false). Provides `BreakoutLevel`. Evidence `NYearHighEvidence`: `level`, `level_date`, `bars_since`, `close`, `pct_above`.

  - `func Signals(c *rules.Compiled, ctx *patterns.Context) []int`: bar indexes t where `Eval(t).Pass && Eval(t-1).Evaluable && !Eval(t-1).Pass` (spec §5.5: a not-evaluable t−1 never signals). Uses only `t < Complete`. Bar 0 never signals.
  - `type Side int` (`Buy`, `Sell`); `type CostModel interface { Cost(notional float64, side Side) float64 }`; `type PercentCost struct{ PerSidePct float64 }`
  - `type Executor interface { FillPrice(ref float64, side Side) float64; Quantity(capital, price float64, inst market.Instrument) int64 }`. `EquityExecutor{SlippagePct float64}` uses buy = ref×(1+s), sell = ref×(1−s), and **whole shares**: quantity = floor(capital / price), where `price` already includes the per-side cost. 0 means "can't afford one share". `LotSize` is ignored for equities.
  - `type ExitReason string` with values `"stop"`, `"trend"`, `"open"`
  - `type Trade struct { Symbol string; SignalDate, EntryDate, ExitDate market.Date; EntryPrice, ExitPrice float64; ExitReason ExitReason; GappedStop bool; ReturnPct float64; HoldingDays int; RankKey float64 }`. `ReturnPct` is net of costs and slippage. `RankKey` is set by `Run` (Task 7), not by `TradePath`: `patterns.RSDiff(ctx, 6, sig)` for **every** system, whether or not RS is in the rule (spec §5.6); `-Inf` when not evaluable. `ReturnPct` is per share, so whole-share sizing doesn't change it.
  - `func TradePath(sig int, ctx *patterns.Context, daily *market.Series, sys *rules.System, ex Executor, cm CostModel) (Trade, bool)`. It returns false if there's no next daily bar to enter on.
- Semantics, all as decided in §5.1, §5.4 and §5.5:
  - **Entry:** daily index `e = sig+1` (daily) or `LastDailyIdx[sig]+1` (weekly). Fill = `FillPrice(open[e], Buy)`.
  - **Stop:** level = `entryFill × (1 − stop_pct/100)`. Checked from day `e` itself, inclusive. On a day with `low ≤ level`: the exit reference is `min(open, level)` and `GappedStop = open < level`.
  - **Trend exit:** on weekly bars of the daily series. For each complete week w whose last daily index is ≥ e, if `close_w < SMA_N(close)` (the SMA includes week w and needs N complete weeks), exit at the open of daily `LastDailyIdx[w]+1`.
  - **Same-day priority:** a trend exit scheduled for day d's open happens before that day's stop check.
  - **End of data:** exit reason `"open"` at the last close, with no exit cost applied.

  - **Single-stock trades (`AllTrades`):** walk signals in order and skip any signal whose entry date falls before the previous trade's exit date. Used for trade-level stats only.
  - **Portfolio candidates:** a `TradePath` for **every** signal. The portfolio skips a candidate only if it currently **holds** that symbol, so a candidate rejected for lack of slots never hides a later signal in the same stock (spec §5.5).

  - **Start date:** max(from, benchmark first date). Bars before it are still loaded for lookback.
  - **Benchmark curve:** buy-and-hold `^NSEI` at the start date's close, same capital.
  - `Survivorship = !hasHistory`.
